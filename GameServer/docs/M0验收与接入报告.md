## 4. 本次排错记录

### 4.1 工具链缺失

旧项目默认 `C:/msys64` 不存在，本机常用目录与 PATH 未找到所需 MinGW32 GCC/NASM。已在 `GameServer/.toolchain` 内建立工具链，未修改系统 PATH、旧源码或原始游戏目录。

下载使用固定版本的 MSYS2 归档；官方源速度慢后改用清华镜像，最终哈希与固定值一致。初始化时密钥刷新出现网络警告，随后软件包验签与安装成功；未禁用签名检查。完整包版本已记录。归档参考：[MSYS2 官方目录](https://repo.msys2.org/distrib/x86_64/)、[清华镜像目录](https://mirrors.tuna.tsinghua.edu.cn/msys2/distrib/x86_64/)。

### 4.2 首次地图加载失败

会话 `.server-runs/f79a9435df69` 未通过。验收器把普通地图名同时传入 `codol_sessionMap`，而目标版本 `load_target_map()` 对普通 MP 要求该任务字段为空，因而在资源加载前拒绝。源码依据：`native/src/codol/assets/codol_asset_commands.c` 的 `load_target_map()`。

修复是删去验收器错误参数，继续使用 `+map mp_cross_fire`。未放松引擎校验、未改写就绪标记。失败现场保留，子进程已由持有句柄的验证器结束；新一轮能够重新绑定同一端口。验证器随后补充了明确地图崩溃的提前终止检查。

### 4.3 保留的非关键提示

日志仍包含 `default_mp.cfg` 缺失、可选 Steam API 未加载、启动时延提示及部分初始化参数只读提示。独立地图实际运行、资源发布校验与主动退出均通过，因此不把这些提示混同为本轮地图失败，也不宣称日志完全无警告。它们需要在发行配置整理时分类处理；当前没有加入外部 Steam 依赖。

## 7. 架构决策与下一步

- 控制服务采用模块化单体，战斗使用独立原生子进程，UI 通过 API 操作。
- 原生版本适配留在边界，不把客户端地址或调试循环引入房间领域模型。
- 玩家、房间与对局使用独立 ID；房间复用但每局 ID 唯一。
- 先保持一个回环战斗端口；独立服务端管理 UI 不需要放开游戏进程网络权限。
- 旧原生引擎和版本协议采用可追溯迁移；上层生命周期、房间与控制服务重写。
- M0 验收工具不升级为生产监督器；M1/M3 增加结构化状态、启动意图、权限、并发与恢复。

下一阶段 M1 的可执行工作：建立 `Server/` 分层与独立环境；配置和日志；数据库初始迁移；管理员本地认证；健康/能力接口；管理 UI 总览；服务启停。M0 运行时能力通过适配器接入，界面不能直接调用任意 RCON。

M2 的先行研究是原生房间事件入口与安全回调消费点；M3 的最大未知仍是新客户端的协议/资源实际接入。M0 已降低构建和独立地图加载风险，没有消除这两项风险。
