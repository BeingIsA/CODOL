# M1 验收与接入报告：独立服务端与管理 UI

日期：2026-10-15。前置：R0 完成（见《R0验收与结构报告》）。要求来源：《服务端与Bot对战实施方案》§9-M1、ADR 0002/0003。

> 后续状态：本报告保留 M1 验收当时的能力边界。M2 已有真实房间通信，重复启动凭据覆盖问题也已补修，当前状态见《M2验收与接入报告》，不能把本报告中的“房间恒空”当作现状。

## 1. 用户现在实际能做什么

在**不启动游戏客户端**的前提下：

1. 双击 `GameServer\control\Start.cmd` 启动控制服务，浏览器自动打开管理页（`http://127.0.0.1:8790/`）；
2. 用初始凭据登录（首次生成于 `control/data/初始管理员凭据.txt`），修改密码；
3. 在管理页查看：服务状态、房间容量（当前恒空，如实说明）、运行时契约预检
   （EXE/审计/镜像/12403 项资产哈希/端口占用）、原生运行历史与脱敏日志；
4. 用 `Stop.cmd` 或页面「停止服务」优雅停服；关闭浏览器页面**不会**停服。

**边界（与实施方案一致）：这只是管理服务就绪，不是游戏对战。**
M1 页面上所有未实现能力（建房、玩家连接、开局、Bot）在能力表里如实为 false。

## 2. 为什么需要这些改动，数据怎样流动

M2 起客户端宿主要连"服务端"，这个服务端必须先能独立存在、被管理、可观察。
M1 建立的就是这个权威进程：SQLite 存配置与审计（重启不丢），领域层定规则，
transport 只做 HTTP 映射，运行时层按 R0 契约做只读预检。数据流：

```text
浏览器(UI) ──HTTP+Bearer──> transport(FastAPI) ──> application 用例 ──> domain 规则
                                                  │                     │
                                    infrastructure（SQLite/令牌/日志）   runtime（契约预检，只读）
```

## 3. 新增模块与旧代码迁移边界

- **全部新写**：`GameServer/control/`（约 20 个源文件，分层见 control/README）；
  唯一框架层是 `transport/`（FastAPI 0.143.1 + uvicorn 0.54.0，锁定于 requirements.lock.txt）。
- **复用既有**：M0 原生 EXE 与验收器（未改动）；契约文件为 M1 与验收器的共同权威。
- **环境独立**：`GameServer/python/`（嵌入式 3.12.0 副本 + pip 锁定依赖），
  不动 Client 内置环境——落实 AGENTS.md 对 M1 的环境要求。
- 布局差异：实施方案原计划新建工作区级 `Server/`，按用户指示并入 `GameServer/`，
  由 [ADR 0003](../../docs/adr/0003-控制服务布局与技术基线.md) 记录；UI 未用 React，
  以无构建静态页交付（同 ADR §4，复杂化时可换前端而不动接口）。

## 4. 自动化与实机各自验证了什么

**自动化（28 项，全部通过；`GameServer\python\python.exe -X utf8 -m unittest discover -s GameServer\control\tests`）：**
令牌签名/过期/篡改、口令散列与策略、未授权 401 边界、登录会话、总览/房间/能力如实性、
契约加载与真实探测器判定（合成工作区的通过/损坏路径）、跨重启改密与帐号保留、
关页不关服、状态一致性、本机停服令牌链路、错误停服令牌拒绝、
端口冲突（真实子进程：退出码 2 + `startup-failure.json`）、
收尾不误删他实例控制文件（本轮实测教训的回归）。

**实机（真实环境，非假探测器）：**
Start.cmd 启动 → 自动初始化管理员 → 真实深度探测全量哈希 12403/12403 通过 →
浏览器实测五页签（总览/房间/诊断含 `.server-runs` 历史/运行时/账户）→
Stop.cmd 停服（中文输出正常、控制文件删除、端口释放）→ 重启后 config.json 与凭据文件
逐字节一致、原口令可登录、帐号未重新初始化 → API 会话停服（UI 按钮同款链路）优雅退出。

## 5. 尚未通过的项目、风险与下一关口

- 本轮发现的 4 个问题已修复并纳入回归：UI 登录后未刷新总览（缺 `refreshAll`）、
  访问日志 detail 被 LoggerAdapter 覆盖丢失、`.cmd` 中文注释在 GBK 控制台破坏解析、
  启动失败实例误删在运行实例的 control.json。
- 未做：TLS/防 CSRF（本地回环+令牌下风险可控，公网前必须补）、离线依赖安装包（M5）、
  `native/tools`、`native/tests` 等结构欠账（R0 报告任务表）。
- 会话令牌跨重启仍有效（无状态 HMAC + 口令版本绑定）；如需"重启即全员下线"，
  在 M2 引入玩家会话时一并设计，当前管理员场景无此需求。
- **下一关口 M2**：客户端原生 UI 建房（开发身份/玩家通道/心跳/CreateRoom/事件推送），
  以及对应结构验收（房间规则独立于原生地址常量、桥接只转换意图）。

## 6. 对照 ADR 0002 的结构验收

- UI/API、领域、基础设施、运行时适配**分离**：`transport` 是唯一 FastAPI 层，
  `domain` 无任何框架/IO 导入，`application` 依赖注入（组合根在 `main.py`）✔
- 生产启动不依赖验收/导入脚本：`main.run` 独立装配，M0 工具保持验收器身份，
  未升级成生产管理器 ✔
- 新代码全部带中文文件/函数注释，说明目的、约束与错误处理 ✔
- 依赖边界已可自动检查的部分：`domain` 无第三方导入（单测覆盖其纯度路径）；其余
  边界以 ADR + 阅读地图约束，导入级 lint 属 M2+ 持续收口项。
